# ADR: Record-local operations with Git sync

Status: decided, not implemented. This replaces the lookup-only proposal in [Bounded, event-driven work](bounded-work-and-card-events.md). It changes the save and authority mechanisms in [Git sync](catalog-git-sync.md), while retaining its separation of local durability, publication and effective ownership. The [effect-planning ADR](effect-planning.md) still governs native effects.

## Make the records sufficient

A Session report should read the Session and its Stream, apply the report, and save the changed records. Today that path repeatedly loads the catalog. With Git backing, it also replays local and confirmed history to recover ownership and prove that the working files agree with supported commits. Making the final record lookup direct would leave those larger dependencies intact.

The records should instead contain everything an operation needs to decide. An operation will read its named records, apply its input as a pure function, and persist the result. Reconciliation belongs inside apply, not in a separate history-driven coordinator around every save. There will be no catalog scan, history traversal or cache on this path, including at process startup. Git sync alone will consult history and merge records between hosts.

The domain model and pure apply function must not depend on YAML, Git or a frontend. Storage reads and writes typed records; a sync strategy merges and shares them. Herdr, cmux and future frontends supply observations and execute their own action types behind interfaces. Neither frontend selection nor sync strategy may change local operation semantics.

This is a data and interaction model change, not a response-time target. Measurements supplied for this decision put `streams --json check` at 0.19–0.24 seconds wall time, about 0.1 seconds CPU, on the current live catalog. Event-driven cards and the long-lived Pi child will remove repeated idle reads and process starts. Those measurements do not justify adding lookup caches or an automatic migration framework. The reason for this change is that ordinary work should depend only on its own records, even as the catalog and its history grow.

## Read, apply, write

Each operation type should declare a small, typed input set: its target, its Stream authority, any captured dependencies, and its own retry receipt. A Session update is not an arbitrary `Catalog` plus an unrestricted vector of inputs. A membership move names one Session, its source Stream and its destination Stream. An asynchronous report retains its original conversation, membership context and captured text inputs. Apply assesses conversation-local and Stream-shared changes separately: a move need not discard valid conversation-local work, but never retargets old Stream prose.

The Session needs a current membership-period identity as well as its Stream ID. Each move creates a new period, even when returning to a previous Stream; returning must not revive an old Stream-scoped report. Captured report context also needs the harness's branch/context generation. Relevant lifecycle events must invalidate that context before older model work can be admitted. These are report-admission inputs, not changes to conversation or native card lifetime identity.

Under local serialization, the shell will read those records once and decode them into valid domain types. Apply will compare the captured base with that current input and return changes, no change, superseded intent or a conflict. A Session report checks Session host ownership, captured branch/context generation and its current Stream's usable local authority, not its pre-move Stream or membership period. A Stream report checks the target Stream's captured authority period and the captured Session's current Stream ID and membership period. Both retain manual-text protection and reuse-of-operation-ID checks. The shell will write only the resulting records and receipt, returning those values rather than reopening the catalog to discover what happened. Unrelated record revisions will not reject the operation.

Strict decoding remains mandatory: supported schema versions, unique object keys, regular files, safe paths, physical identity, and relationships among the named records. A malformed record is not absence. New record creation must distinguish a missing key from an unreadable or conflicting one. Whole-catalog checks move to explicit catalog inspection and sync, not an implicit precondition of opening a backend handle. `list` and `check` may enumerate current records; neither should replay Git history. A historical audit belongs to sync or its explicit inspection mode.

Local saves will no longer depend on creating or verifying a Git commit. They will acknowledge durable record changes, not claim publication. A sync trigger may be emitted after a save, but sync runs as a separate operation; a due publication check must not hide a catalog scan inside a report response. Sync failure cannot turn an accepted local report into a clean failure that invites a duplicate action.

### Membership move contract

A membership move has exactly 3 catalog inputs: the Session, the old Stream and the new Stream. The Session supplies the old Stream key; the verified destination supplies the new one. The domain entry point accepts these typed records and the verified move input, not a complete `Catalog`. It reads stored authority from both Streams and applies reconciliation purely over those inputs.

The storage interface must support one catalog-locked read → apply → save of that 3-record set, including its captured revisions. It must not implement the move as separate Session and Stream saves, or validate unrelated records first. Apply returns the resulting set or an explicit no-change/conflict outcome. One save installs the set; unchanged records retain their revisions. A missing named destination is a typed creation case with new-Stream authority rules, never permission to select another Stream by scanning.

The Stream stores its member Session IDs. Apply removes the Session from the old Stream's set, adds it to the new Stream's set, and changes the Session's membership and period in that same save. No other Session records are inputs. Operation receipt and recovery fence are fixed transaction machinery, not extra catalog dependencies. Native relationship/evidence changes are separate effect plans under their own locks; they must not add other Sessions to this catalog operation.

### Durability without history as a journal

Stable operation IDs and exact-intent fingerprints remain necessary. A retry must not apply twice, become a different operation after a lost acknowledgement, or reuse an ID with changed intent. Store that evidence by operation ID, with the target identities and accepted outcome. Read only the operation's own receipt, not the current host-wide receipt map or Git log. This is durable deduplication evidence, not a cache of derived catalog state.

Atomic replacement of one file does not make a move or enrollment atomic across files. The local write protocol must durably fence the named write set before replacement and record completion before acknowledging it. A fixed recovery marker can identify the exact records and receipt involved; it must not require scanning for pending transactions. Interrupted or ambiguous writes stay repair-required. Recovery uses the retained bytes and intent, not a history replay on the next operation. This ADR does not authorise automatic rollback or retry.

The same rule applies when sync installs several merged records. Readers and writers must not accept half an ownership transition or a Session whose membership points to a not-yet-installed Stream. Serialization and the durable fence establish the local visibility boundary. Any selected protocol must preserve these guarantees before replacing today's full-snapshot save checks.

## Authority is record state

The Stream record will carry effective authority, including the owning host and an ownership-period identity. That identity must change for every effective transfer, including a transfer back to an earlier host. The creation or transfer operation ID can identify that period, as it does today. It cannot be a Git commit hash, a wall-clock timestamp or merely the owner host's name. Captured operations compare it with the current Stream record.

The record must distinguish effective authority from proposed ownership. Preserve the existing activation rules: creation of a genuinely new Stream establishes local creator authority immediately; an existing Stream's handover does not grant the destination authority until sync confirms publication. An authorised operation records the pending transition. Sync records its activation or its unresolved outcome in the same Stream record. Model-generated prose and ordinary field edits cannot set these authority fields.

The schema must represent usable authority separately from unresolved or conflicting ownership, using typed states rather than a collection of optional flags. The existing `owner` field must not disagree silently with that state. Reads can display a conflict, but automatic catalog and native effects requiring that authority must refuse it. Host-local workspace evidence and a card's launch context cannot supply missing Stream authority.

This is not a host-local memo of a history calculation. The versioned Stream is the authoritative input to local operations, and both operation and sync writers must preserve its invariants. There is no cache miss that falls back to history. Migration establishes the first stored authority from existing validated provenance; subsequent changes are explicit record transitions.

Stored authority records this replica's confirmed knowledge. It cannot prove that a disconnected former owner has stopped. Retain the existing stale-owner rejection at sync; do not claim that this redesign provides globally instantaneous revocation or newly enables cross-host native participation.

## Locate records from stable identities

Session identity remains `(host, harness, native session ID)`, as defined by the [native reconciliation ADR](native-context-reconciliation.md). It must locate one portable Session file directly. Membership is not part of that location.

Use a deterministic Session ID derived from that identity; the existing `agent::session_id_for` already computes a host-and-harness-scoped UUID. Its canonical physical path should be `conversations/<derived ID>.yaml`. The ID already includes host identity; a flat directory lets a Stream's member IDs locate files without a host lookup. Derive and verify both ID and path from the record's native identity, not from a hint or an unverified filename. Change legacy IDs at cutover rather than maintain an alias index. Writers and captured requests must carry the full Session identity. A card already has it in its scope.

An exact Stream ID locates its Stream file. The proposed CLI contract changes too: single-record and mutating commands require exact IDs or verified current context, rather than today's title and substring matching. Title search and candidate selection belong to explicit `list` or `session list` discovery, which returns exact keys for the subsequent operation. No one-off CLI, Pi child startup or stale reference should fall back to catalog enumeration. A missing Session means unenrolled; an invalid or ambiguous migrated identity means repair. Sync validates uniqueness across the catalog before installing records.

The directory binding stays host-local and per Session, under a deterministic Session key. The checkout registry stays host-wide. Neither belongs inside the portable Session. Read the registry once and pass its decoded value through directory and document resolution, rather than rereading it for each repository. Stream-only directory defaults remain separate, keyed by Stream. A Session checkout must always carry its resolved portable repository URL, populated at attach or creation; a Stream-local alias is only a label. A Stream repository edit then cannot orphan an unread Session. A membership move preserves that URL and the Session's directory binding; it does not reinterpret old aliases through the destination Stream.

The Stream's member Session IDs are authoritative relationship state, not a rebuildable index. `open`, `resume`, `show`, capture and handover read the Stream, then exactly its named Sessions. They never discover members by scanning the catalog or depend on a live frontend to enumerate them. Enrollment and moves maintain both sides of membership in one catalog save. The read set can grow with that Stream's roster, but not with unrelated catalog records.

Native workspace relationships also need direct addresses. Current enrollment and workspace checks enumerate associations, claims and pending attempts to establish exclusivity. The replacement must represent reservations and relationship phases at their enforcement keys: the native workspace and the host's Stream association. Reading those few records must establish the same exclusions without searching every relationship. They are authoritative relationship records, not a best-effort reverse-lookup cache. A disagreement or unresolved reservation blocks the action; it must not be repaired by guessing from a live pane address.

## Native actions use the same boundary

A native operation will read its own records and take one fresh native snapshot under the native lock, then apply observations and plan actions as pure data. The executor carries out that ordered plan, preserving record-intent → effect → record-outcome. A mismatch or uncertain outcome stops the plan and retains its fence. Native display, observation and effect permissions remain distinct; the pure apply step does not turn a card into a writer of catalog membership.

Card lifetime and native evidence identity are owned by [Card lifetime and native evidence](native-context-reconciliation.md): catalog-scoped conversation identity plus launch nonce. Current Stream membership and owner location are observations, not identity or write authority. The child acts; the card observes. This ADR does not introduce a competing attempt key or relax inherited-ID bootstrap checks.

That contract requires one conversation-keyed evidence record and the completed-format marker. Name ownership ledgers remain direct records for the affected workspace and tab. Offline `streams native migrate-evidence` archives old bytes and quarantines unattributable attempts for explicit resolution. The marker is installed only after legacy records and quarantined uncertainty are resolved. Normal operations never read legacy keys or support a mixed layout; a new key cannot bypass an unresolved attempt's fence.

## What sync must establish

Sync may enumerate records and consult Git history to establish the common base, producer provenance and publication evidence. It will merge structured records, not grant authority because a text merge succeeded or replay the catalog before each later operation. Independent fields may merge; changes to the same field on both sides conflict. Member rosters use three-way set merges. Competing lifecycle, membership and ownership transitions remain subject to their domain invariants.

For each Stream, sync must compare the base and both sides' effective ownership periods and pending transitions. A legitimate confirmed handover activates exactly its recorded successor period. A stale former-owner update cannot freshen its authority or be relabelled as work by the successor. Conflicting creations of the same identity, incompatible transfers, invalid provenance or a missing authority state must not select a winner by timestamp, host preference or Git ancestry alone.

On an authority conflict, preserve both inputs and publish nothing under the existing all-or-nothing conflict policy. Materialise a fenced ownership state for affected local operations, or fence installation of the candidate before any affected operation can proceed. Leaving an apparently usable authority beside an unseen known conflict is not fail-closed. Preserve unrelated local saves and expose the decision needed from the user; do not erase either side as repair.

Validate the merged catalog's Session uniqueness, both directions of roster membership, repository references and authority state before installation. A set merge cannot make one Session a member of conflicting Streams. Sync takes base, local and remote records and writes a sync snapshot, replacing today's one-operation-envelope-per-commit format. Local pure apply enforces actor and captured-input guards once; sync does not reconstruct or replay operations from retry receipts. If remote inputs change while local prose reflects older inputs, both can merge and the prose may be stale until the next report. This is an accepted consequence for generated prose in alpha software, not a reason to retain an operation log. A record snapshot alone is not proof that an earlier operation was acknowledged or published.

A sync candidate may encode the successor authority for publication, but it is not an input to local operations before confirmed installation. Another host adopts that published state only through sync's provenance and transition checks. This avoids requiring a second publish merely to label the first one confirmed.

Confirm publication and persist the resulting authority and records under the local write protocol. Unknown push or adoption outcomes retain their durable fence; the next ordinary operation must not consult history to resolve them. Explicit sync or recovery resolves them. Only sync writes Git commits and advances its transport baseline. Host-local directory selections, checkout registry and native launch evidence are never merged through Git.

## Explicit cutover

Use one explicit deploy migration after a backup, not compatibility probes on every read. This is alpha software: change the schema, discard and regenerate derived prose where needed, and do not preserve every old ID or partial format. Stop old writers and event consumers, acquire the owning locks, and derive stored effective/pending authority from existing validated receipts and Git provenance. An unconfirmed owner field must not become effective authority.

Translate unambiguous Sessions to the deterministic IDs and identity-based paths, whether they came from legacy Stream partitions or old canonical paths. Translate the references needed for usable new records, populate each Stream's member IDs, and resolve every checkout URL from its existing Stream; otherwise reject or recreate those generated records. Invalidate old captured requests at the schema/context-version boundary. There is no old-ID alias service, and later membership changes do not relocate files.

Promote directory selections to their new per-Session keys, including selections saved before a membership move. Put Stream-only defaults in a separate Stream-keyed directory. Do not select among contradictory bindings by directory order or timestamp: require an explicit choice or clear and reselect them. Keep the 4 record classes separate. New readers reject an old or incomplete format; `check` and sync report leftover legacy state instead of enabling fallback. A versioned completion boundary is written only after the usable new records are durable, and old writers must reject it.

Migrate or reset runtime associations, enrollment claims and arrangements to the new workspace-keyed and host-Stream-keyed relationship records. Pending workspace-open attempts must retain their uncertainty fences; resetting generated relationships must not permit duplicate effects.

Native evidence is the safety exception to discarding generated state. Follow its own attribution and nonce-preservation contract. Do not rekey an attempt merely because a Session ID changed, and do not discard an uncertain attempt while its external resource might exist. An unprovable attempt stays fenced for explicit recovery, without a compatibility subsystem on the normal path. Deploy automation, not a report or card read, runs the cutover; this ADR never authorises touching live state.

## Inventory and operation budgets

The inventory below describes the current source, not the unmerged native reconciliation work. Common current costs are `application::open` → full snapshot; `agent::context` → another snapshot plus authority read; local authority → all creation receipts and a snapshot; Git authority → local and confirmed history. `YamlTransaction::save` reads the complete catalog before and after replacement and compares the whole revision map. These dependencies must disappear, not merely move behind a direct lookup API.

The proposed sets exclude fixed configuration/producer/schema reads and locks, but tests must count those separately by name. A mutating catalog operation also reads its own operation receipt and a fixed recovery fence. No allowance permits a host-wide receipt enumeration. A native action adds its own conversation evidence and only the relationship/name records it uses. Single-Session file counts are independent of unrelated Streams, Sessions and history length. Stream-wide operations read one Stream and exactly its member Sessions; count that declared per-member budget rather than hiding a catalog scan. The one host-wide checkout registry is read once, not once per repository.

Stream report: target Stream + captured Session; check captured authority and membership periods. Add only typed captured dependencies, own receipt and recovery fence; write changed target and receipt. No Git commit, inline sync or whole-catalog revision comparison. |
| Card read / ordinary context | Repeated complete snapshots and authority; all Stream Sessions for handover; per-Session binding with legacy discovery; registry rereads for binding, primary checkout and repositories; document file checks | 1 Session + 1 Stream + 1 Session binding + 1 registry. Stable identity supplies paths; stored Stream authority removes provenance reads. Return only this Session. Native evidence and snapshot are separate event inputs. Document checks happen only for this Stream's documents when required, not on every native event. Handover inventory is a separate Stream-wide request using the stored member IDs. |

No host-local runtime records enter the merge. |

The checkout registry and a Stream's own documents can grow with that record's contents. The contract bounds the addressed records and forbids unrelated-catalog work; it does not claim every file has constant byte size. Workspace-wide inventory likewise cannot be called a single-Session operation by hiding a loop inside its reader.

Counting tests should assert the named files and directory listings for each operation, including setup, receipt and recovery reads. Grow an unrelated catalog and history and require identical counts. Add strict-decoding, stale-epoch, lost-acknowledgement, move-race and interrupted-write cases. Whole-catalog tests must cover conflicting stored authority and migration failures. Timing is not the acceptance test.
